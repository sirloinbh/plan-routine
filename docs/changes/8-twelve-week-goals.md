# #8 12주 루틴: 목표 재설정과 회고

- 이슈: [#8](https://github.com/sirloinbh/plan-routine/issues/8)
- 브랜치: `feat/8-twelve-week-goals`
- 일자: 2026-11-01 (Asia/Seoul)

## 목적

12주마다 목표를 다시 세우고 지난 12주를 돌아본다. 기간은 앱 첫 사용일이 속한 주의 일요일부터 84일씩이다(#3에서 확정).

## 확정한 규칙 (사용자 확인, #8 코멘트 기록)

- 목표를 하루·주간 루틴과 연결하지 않는다. 연결은 [#52](https://github.com/sirloinbh/plan-routine/issues/52)로 분리했다.

## 구현하면서 정한 세부 규칙 (#8 코멘트 기록)

- 목표는 지금 12주 기간에만 추가·수정·삭제할 수 있다. 지난 기간의 목표는 그대로 남고, 회고만 쓰거나 고칠 수 있다.
- 회고는 지난 기간의 목표마다 달성·미달성·미정과 메모(1000자 이하)로 남긴다. 진행 중인 기간의 목표는 회고할 수 없다.
- 회고를 끝내지 않아도 새 목표를 쓸 수 있다. 대신 회고할 기간을 화면 맨 위에 보여 준다.
- 지금 기간의 목표 삭제는 확인을 한 번 더 받고 실제로 지운다. 체크 기록이 달려 있지 않아 보관하지 않는다.
- 목표 이름은 200자 이하다.
- 체크 항목 "목표 재설정"은 마이그레이션으로 한 번만 넣는다. 보관해도 다시 생기지 않는다.

## 변경

- DB(`database/migrations/004_twelve_week_goals.sql`): `twelve_week_goals` 테이블과 체크 항목 "목표 재설정". 재실행해도 안전하다. 기존 DB에는 `database/README.md`의 절차로 적용해야 한다.
- API(`backend/src/goal-routes.ts`, `/api/goals`)
  - `GET`: 지금 기간과 남은 주, 목표, 지난 기간별 목표와 회고(최근 기간부터).
  - `POST`: 지금 기간에 목표 추가. 기간은 서버가 정한다.
  - `PATCH /:id`, `DELETE /:id`: 지금 기간의 목표만 수정·삭제한다.
  - `PUT /reviews`: 여러 목표의 회고를 한 트랜잭션으로 저장한다. 하나라도 잘못되면 모두 취소된다.
- 화면(`frontend/src/twelve-week.tsx`, 메뉴 "12주 루틴", `/twelve-week`): 회고할 지난 기간, 이번 12주 목표, 체크리스트와 항목 관리(`PeriodRoutines` 재사용), 회고를 마친 지난 기간 순서다.
- `frontend/src/labeled-textarea.tsx`: 일기 화면의 글자 수 표시 입력칸을 회고 메모와 함께 쓰도록 옮겼다.

## 검증

- 로컬(`TEST_DATABASE_URL` 제거): 포맷·lint·타입 검사·빌드 통과, 스킬 검사 4 pass. 백엔드 테스트 61개 중 49 pass / 0 fail / 12 skip이며, skip 12건은 DB 통합 테스트다. 프론트엔드 테스트는 `--testTimeout=60000`으로 146개 중 144 pass / 0 fail / 2 skip이다(skip은 #7 기록과 같은 다크 모드 전용 공통 테스트).
- 브라우저: 메모리 기반 임시 API에 Vite 개발 서버를 연결하고 헤드리스 Chrome으로 확인했다. 콘솔 오류는 없었다. 실제 DB와 연결한 화면은 확인하지 못했다. 기간·남은 주·거부 규칙은 임시 API가 아니라 API·DB 테스트로 확인한다.

  - 두 크기 공통: 회고할 기간이 맨 위에 표시, 회고 저장과 안내, 목표 추가, 항목 "목표 재설정" 체크.
