# #64 일기를 탭 두 개에서 쓸 때 임시 글을 잃지 않게 하기

- 브랜치: `fix/64-diary-two-tabs`

## 목적

임시 글은 하나뿐이라, 탭 두 개에서 쓰면 나중 입력이 앞 탭의 글을 경고 없이 덮어썼다.

## 결정

사용자가 선택지는 추천안으로 진행하라고 해 `storage` 이벤트로 감지하는 방식을 골랐다. 날짜별 임시 글은 "화면이 임시 글의 날짜로 열린다"는 규칙까지 바꿔야 하고, 드문 경우에 비해 크다. 이슈 코멘트에 기록했다.

## 변경

`frontend/src/diary.tsx`, `diary-draft.ts`.

- 저장하지 않은 글이 있는 탭에서, 다른 탭이 임시 글을 덮어쓰면 "임시 저장되어 있지 않아, 떠나면 사라집니다"라고 알리고 탭 닫기 경고를 켠다. 이 탭에서 다시 입력하면 임시 글을 되찾고 경고가 꺼지며, 그때는 다른 탭이 같은 경고를 받는다.
- 다른 탭이 임시 글을 지우면(저장하거나 버려서) 이 탭의 글을 다시 보관한다.
- 메뉴 이동은 탭 닫기 경고가 뜨지 않으므로, 글이 사라질 수 있다는 안내만 화면에 남는다.

## 테스트

`frontend/src/diary.test.tsx`: 덮어쓰기 경고와 되찾기, 지워진 임시 글 복구, 저장할 글이 없는 탭, 다른 저장 키.

## 검증

- 로컬: `env -u TEST_DATABASE_URL npm run check` 통과. 백엔드 161개 중 142 pass, 0 fail, 19 skip(DB 테스트), 프론트엔드 277개 중 275 pass, 0 fail, 2 skip, `test:skills` 4개 pass.
- 브라우저: 임시 API와 헤드리스 Chrome의 실제 탭 두 개로 확인했다. B가 입력하면 A에 경고가 뜨고 임시 글은 B의 것이 된다. A가 다시 입력하면 A의 경고가 꺼지고 B에 경고가 뜨며 임시 글은 A의 것이 된다. 실제 탭 닫기 경고 창은 보지 못했다.

## 한계·후속

- 덮어쓴 쪽 탭이 먼저 닫히면, 경고가 켜진 탭의 글은 그 탭이 열려 있는 동안만 남는다. 그 탭을 닫을 때 경고가 뜬다.
